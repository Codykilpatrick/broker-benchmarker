High CPU Usage

WARNING / CRITICAL

What This Means

One or more Redpanda reactor shards are running at or near 100% CPU. Redpanda uses a thread-per-core model — a saturated shard will cause latency spikes and may drop requests.

Likely Causes

  • Throughput exceeding the broker's single-node capacity
  • Too many partitions assigned to too few cores (--smp)
  • Compaction or internal background tasks running hot
  • High produce rate with small messages (high request overhead)

Recommended Actions

  1. Identify which shard is hot — check CPU Busy panel per shard legend.
  2. Reduce produce rate or GBPS_TARGET in the benchmarker to back off load.
  3. Increase --smp in the Redpanda docker-compose command to give it more cores.
  4. Increase linger.ms and batch.size on producers to amortise CPU cost per byte.
  5. Reduce partition count — fewer partitions per shard lowers scheduling overhead.
  6. Check whether compaction is running: 
    curl -s http://localhost:9644/v1/debug/storage

Metrics to Watch

  • redpanda_cpu_busy_seconds_total — per-shard CPU time
  • redpanda_kafka_request_bytes_total — incoming load
  • redpanda_scheduler_runtime_seconds_total — reactor runtime
