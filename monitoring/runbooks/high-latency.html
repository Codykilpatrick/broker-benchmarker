High Request Latency

WARNING / CRITICAL

What This Means

Kafka request latency (p95 or p99) has exceeded the alert threshold. Producers and consumers may be experiencing slow responses, which can cause backpressure, consumer lag, or timeouts.

Likely Causes

  • Broker CPU saturation — a shard is near 100% busy
  • Partition count too high for available memory/CPU
  • Large message sizes causing I/O pressure
  • Insufficient linger.ms or batch settings causing too many small requests
  • Disk I/O bottleneck (slow fsync)

Recommended Actions

  1. Check the CPU Busy panel in Grafana — if any shard is near 1.0, the broker is CPU-bound.
  2. Check the Kafka Bytes In/Out rates — if throughput is near the NIC limit, consider scaling.
  3. Reduce partition count if it exceeds cores × 1000 guideline.
  4. Tune producer linger.ms (try 5–10ms) and batch.size to reduce request frequency.
  5. Check disk I/O with: 
    docker exec monitoring-redpanda-1 iostat -x 1 5
  6. If running on Docker Desktop (Mac/Windows), note that disk I/O is virtualised and will be slower than bare metal.

Metrics to Watch

  • redpanda_kafka_request_latency_seconds_bucket — histogram of request latency
  • redpanda_cpu_busy_seconds_total — per-shard CPU utilisation
  • redpanda_kafka_request_bytes_total — throughput rate
