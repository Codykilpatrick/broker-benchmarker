Low Disk Space

WARNING

What This Means

The Redpanda data directory is running low on free space. If disk fills completely, Redpanda will stop accepting writes and the broker will become unavailable.

Likely Causes

  • Retention policy not configured — logs growing unbounded
  • High write throughput with no segment cleanup
  • Docker volume on a small partition

Recommended Actions

  1. Check current disk usage: 
    docker exec monitoring-redpanda-1 df -h /var/lib/redpanda
  2. Set a retention policy on benchmark topics to free space: 
    docker exec monitoring-redpanda-1 rpk topic alter-config benchmark_64kb_0 \
  --set retention.bytes=536870912
  3. Trigger log cleanup manually: 
    docker exec monitoring-redpanda-1 rpk cluster storage recovery start
  4. For the benchmark specifically — delete and recreate topics between runs to avoid accumulation: 
    docker exec monitoring-redpanda-1 rpk topic delete benchmark_64kb_0 benchmark_1mb_0 benchmark_12mb_0 benchmark_32mb_0
  5. If running persistently, add a Docker volume size limit or move the data directory to a larger disk.

Metrics to Watch

  • redpanda_storage_disk_free_bytes — free bytes on data partition
  • redpanda_storage_disk_total_bytes — total capacity
